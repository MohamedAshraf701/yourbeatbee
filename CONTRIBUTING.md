# Contributing to YourBeatBee

Thank you for your interest in contributing! We welcome issues, feature requests, bug fixes, documentation improvements, and more.

## Getting started

1. Fork the repository.
2. Create a branch: `git checkout -b feat/my-feature` or `git checkout -b fix/issue-123`.
3. Install dependencies: `pnpm install` or `npm install`.
4. Run the dev server: `pnpm dev` or `npm run dev`.
5. Run tests (if any): `pnpm test` or `npm test`.

## Branching & commits

- Use descriptive branch names (feat/, fix/, docs/).
- Follow conventional commits where possible: `feat:`, `fix:`, `chore:`, `docs:`.
- Keep PRs small and focused.

## Pull request process

- Open a pull request against the `master` branch from your feature branch.
- Include a clear title and description explaining the change and motivation.
- Reference related issues with `Fixes #<issue-number>` when applicable.
- Ensure any tests pass and linting/formatting is applied.

## Code style

- We use Prettier for formatting. Run `pnpm format` or `npm run format`.
- Be consistent with existing project patterns (TypeScript, Next.js app structure).

## Tests

- Add tests for new features or bug fixes when possible.

## Security

If you discover a security vulnerability, please see SECURITY.md for reporting details.

Thank you for helping make YourBeatBee better!
